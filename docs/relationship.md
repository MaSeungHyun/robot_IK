# 연결관계 
역할들은 오브젝트 종류를 바꾸는게 아닌 같은 glb 기준으로 나뉨.
(역할을 바꾼다고 모델이 바뀌면 안됨.)
   
### 입하 
1. 팔레트 AMR인 경우,
팔레트 입하 컨베이어와 상호작용하되, 팔레트 AMR의 상단이 비어있어야함
   1. 팔레트가 있는 경우 forklift가 해당 팔레트를 여분 팔레트 적재공간에 내려주어야 다음 팔레트를 받을 수 있음
   2. 박스가 나오는 컨베이어와 상호작용이라면 로봇을 통해 AMR위 팔레트에 적재 받음. 팔레트가 없는 경우라면 forklift에게 팔레트를 받아야함.

### 스캔 과정
1. 스캔 시작 부분에 로봇이 필요함 -> 박스 하나씩 스캔하기 위해서
2. 검사결과가 있는 박스는 상단에 팔레트가 있는 AMR이 받음.
   1. 이때, 팔레트가 없는 경우 여기도 forklift가 팔레트를 올려주어야함.
   2. rack_m은 agv와 한 세트로, rack_m에 적재되어 있다면, agv를 통해 rack 근처에 rack 적재를 하는 forklift 근처로 배달.
   이때, rack_m이 없다면 amr은 적재 forklift에게 가서 forklift가 amr위 팔레트를 rack에 적재 후, 적재가 끝난 forklift나 근처 여분 forklift가 amr위에 팔레트를 다시 놓고 반복.

### 출하
1. forklift가 출하 컨베이어 근처 로봇에게 팔레트를 가져가거나 forklift가 amr 위에 팔레트를 올려주면 해당 amr은 출하 근처 로봇에게 가져가면 로봇은 해당 박스를 출하 컨베이어 벨트에 하나씩 올림.
2. 출하컨베이어가 팔레트 전용이라면 로봇 없이 AMR이 로봇 없이 출하 컨베이어 시작점으로 가 팔레트를 컨베이어로 밀어서 출하시킴.


* 입하되는 팔레트와 박스에 대해서 박스는 무조건 스캔이 되어야하므로 개별 박스로 떼어내는건 로봇이므로 로봇을 무조건 거쳐야하며, 출하에는 팔레트 자체를 내보낼 수 있으므로 로봇은 필수가 아님.
