# 모듈형 컨베이어 GLB 가이드 v2 (디자이너 / 개발자)

모듈형 컨베이어 GLB를 Three.js에서 **조립 → 자동 연결 → 박스 이동 → 불량 분기**까지 처리하기 위해, 디자이너와 개발자가 각각 지켜야 할 규칙을 정리한 문서입니다.
(v1 대비 변경: 다중 줄 이름 규칙, 직선 구간 표시 `_L`, 자동 연결 판정, 분기 이름 정리)

## 0. 핵심 원칙

| 대상 | 의미 | 비고 |
|---|---|---|
| `CONN_*` (Empty) | **바깥과 연결되는 지점** (스냅/연결 판정 대상) | 모듈 사이 연결은 여기서만 일어남 |
| `PATH_*` (Empty) | 모듈 **내부**의 중심선이 지나는 점 | 곡선/꺾임을 표현 |
| `STATION_*` (Empty) | 줄 중간의 **기능 위치** (센서, 분기 등) | 필요할 때만 |

- **Empty는 위치와 방향을 알려주는 표식이고, 경로(spline)는 코드가 런타임에 만든다.**
- Blender의 Curve 오브젝트는 glTF로 내보내면 곡선 정보가 남지 않고 메시로 바뀌므로, 곡선 데이터는 Empty 위치로 전달한다.
- **경로는 모듈 단위로 만들고, 연결된 모듈끼리 이어 붙인다.** 모든 점을 하나의 spline으로 합치지 않는다. (직선이 휘는 것을 방지하고, 모듈 교체가 쉬움)

```
모듈 A: CONN_1_IN ───────────────────── CONN_1_OUT       (PATH 없음 → 직선)
                                              │ 가까이 붙음 (OUT ≈ IN)
모듈 B: CONN_1_IN ─ PATH_1_00 ─ PATH_1_01 ─ PATH_1_02 ─ CONN_1_OUT   (곡선)
```

## 1. 이름 규칙 (디자이너 / 개발자 공통)

줄 번호는 **1부터** 시작하고, **모듈 안에서 진행 방향 기준 왼쪽부터** 1, 2, 3으로 센다. 모든 모듈이 같은 기준을 쓴다.

| 이름 | 개수 | 용도 |
|---|---|---|
| `CONN_<줄>_IN` | 줄마다 1 | 입구 위치와 방향 |
| `CONN_<줄>_OUT` | 줄마다 1 | 출구 위치와 방향 |
| `CONN_<줄>_OUT_<출구>` | 분기 줄만 | 분기 출구 (`_0` = 합격, `_1` = 불량 …) |
| `PATH_<줄>_<nn>` | 곡선/꺾임이 있는 줄 | 중심선 통과점, `nn`은 **두 자리** 순서 |
| `PATH_<줄>_<nn>_L` | 직선 구간이 있는 줄 | "**이전 점 → 이 점**은 직선"이라는 표시 |
| `BRANCH_<줄>` | 분기 줄만 | 경로가 갈라지는 지점 |
| `BPATH_<줄>_<출구>_<nn>` | 분기 줄만 | 분기 출구로 가는 곡선의 중간 통과점 |
| `STATION_<줄>_<nn>` | 선택 | 센서/푸셔 등 기능 위치. `extras.kind`로 종류 지정 |
| `BELT…` (메시) | 선택 | 벨트 텍스처 스크롤 대상 |
| `PUSHER` (노드) | 선택 | 밀어내는 암/플레이트 메시 |

- **한 줄짜리 모듈**은 줄 번호를 생략한 `CONN_IN`, `CONN_OUT`, `PATH_<nn>`을 1번 줄로 간주한다.
- 점 개수는 줄마다 달라도 된다 (`PATH_1_00~02`, `PATH_2_00~03`).
- 분기 출구가 하나뿐인 일반 줄은 `CONN_<줄>_OUT`(번호 없음)을 0번 출구로 본다.

### 예시: 줄 3개짜리 곡선 모듈

```
CONN_1_IN   CONN_1_OUT   PATH_1_00  PATH_1_01  PATH_1_02
CONN_2_IN   CONN_2_OUT   PATH_2_00  PATH_2_01  PATH_2_02  PATH_2_03
CONN_3_IN   CONN_3_OUT   PATH_3_00  PATH_3_01  PATH_3_02  PATH_3_03  PATH_3_04
```

### 예시: 직선 → 곡선 → 직선이 이어진 한 줄 (한 GLB 안에서)

```
CONN_1_IN
PATH_1_00_L          ← 직선 (IN → 여기)
PATH_1_01            ← 곡선 시작
PATH_1_02
PATH_1_03
PATH_1_04_L          ← 직선
CONN_1_OUT
```

### 출구 역할 (`extras`)

```
CONN_1_OUT_0   extras: { "role": "pass"   }
CONN_1_OUT_1   extras: { "role": "reject" }
```

- 출구 번호에만 의존하지 말고 `role`(`pass` / `reject` / `rework`)을 명시한다.
- 의미를 `extras`로 적는 방식은 이름이 달라져도(`.001` 등) 안전하다. 이름이 기본, `extras`가 있으면 `extras`가 우선한다.

## 2. 디자이너가 고려할 점

### 2-1. 이름과 Blender 제약

- Blender는 **파일 하나 안에서 오브젝트 이름이 유일**해야 한다. (컬렉션이 달라도 동일)
- 그래서 **모듈마다 `.blend`/GLB를 따로 두는 것**을 권장한다. 다른 파일이면 `CONN_1_IN`이 여러 모듈에 있어도 문제없다.
- 한 파일에 모듈을 모아야 한다면 `.001`이 붙는 이름이 생기는데, Three.js 로딩 시 `.`이 제거되어 이름이 바뀐다. 개발자가 파싱에서 뒤 숫자를 무시하도록 처리하므로, **순서 번호(`nn`)를 반드시 두 자리**로 맞춘다.
- 이름은 **영문, 숫자, 밑줄(`_`)만** 쓴다. 공백, 점(`.`) 금지.

### 2-2. 커넥터 규칙 (가장 중요)

- **모든 `CONN_*_IN` / `CONN_*_OUT`의 축 방향 규칙을 모든 모듈에서 똑같이 한다.**
  예: "진행 방향 = Blender +Y, 위쪽 = +Z". 어떤 축이든 상관없지만 전 모듈이 같아야 한다.
- 위치는 **벨트 윗면 중심 높이**에 둔다. 박스는 이 높이에 얹힌다.
- 곡선 모듈에서 `OUT`은 **출구 쪽 진행 방향**을 바라봐야 한다.
- **모든 모듈에서 줄 간격이 같아야** 한다. 간격이 다르면 줄 하나는 맞고 나머지는 어긋난다.
- 줄 수가 다른 모듈은 바로 이어 붙이지 않는다. 줄 수를 바꾸는 연결부는 별도 모듈로 다룬다.

### 2-3. PATH 배치 규칙

- 곡선 모듈은 90° 기준 **5~8개** 정도로 중심선 위에 순서대로 찍는다.
- **`PATH_00`은 입구에서 진행 방향으로 조금 들어간 곳**에, **마지막 PATH는 출구 직전**에 둔다. 곡선의 시작/끝 방향이 모듈 진행 방향과 맞아서 이웃 모듈과 부드럽게 이어진다.
- 직선으로 오는 점은 이름 끝에 `_L`을 붙인다. 직선 구간은 양 끝 점 두 개면 충분하다.
- PATH가 없는 모듈은 `IN → OUT` 직선으로 처리된다.

### 2-4. 메시 / 내보내기 규칙

- 단위는 **1 unit = 1 m**.
- 모든 오브젝트에 **Scale / Rotation Apply**를 한 상태로 내보낸다. (비균등 스케일 금지)
- 벨트 UV는 **V 방향이 진행 방향**이 되게 하고 타일링되도록 한다.
- glTF 내보내기에서 **Y-up 변환**은 기본값(켜짐)을 유지하고, `extras`를 쓰면 **Custom Properties**를 체크한다.

### 2-5. 디자이너 체크리스트

- [ ] 모든 줄에 `CONN_<줄>_IN` / `CONN_<줄>_OUT`이 있다
- [ ] 커넥터의 축 방향 규칙이 모든 모듈에서 동일하다
- [ ] 커넥터와 `PATH` 점이 벨트 윗면 높이에 있다
- [ ] `PATH_<줄>_<nn>`이 두 자리 번호로 순서대로 있고, 직선 구간에 `_L`이 붙어 있다
- [ ] 곡선의 첫/끝 PATH가 입구/출구 근처 진행 방향 위에 있다
- [ ] 분기 모듈에 `BRANCH_<줄>`, `CONN_<줄>_OUT_<출구>`, `BPATH_…`가 있고 `role`이 적혀 있다
- [ ] 모든 모듈의 줄 간격이 같다
- [ ] Scale/Rotation을 Apply했고 단위가 m이다
- [ ] 노드 이름에 공백, 점(`.`), 한 파일 내 중복이 없다
- [ ] **직선 / 90° 곡선 / 분기 샘플 3종**을 먼저 개발자에게 전달해 검증했다

## 3. 개발자가 고려할 점

### 3-1. 파싱

```js
const reConn = /^CONN(?:_(\d+))?_(IN|OUT)(?:_(\d+))?\d*$/;   // 줄(생략=1), 종류, (출구)
const rePath = /^PATH(?:_(\d+))?_(\d{2})(_L)?\d*$/;          // 줄(생략=1), 순서, 직선 여부
const reBPath = /^BPATH_(\d+)_(\d+)_(\d{2})\d*$/;            // 줄, 출구, 순서
// 뒤에 붙는 \d* 는 Blender의 .001 → 001 같은 접미사를 무시하기 위한 것
```

- `gltf.scene.clone(true)`로 모듈 인스턴스를 만들고, 파싱 시점의 `matrixWorld`(루트 기준)를 커넥터/PATH 행렬로 저장한다.
- 결과 구조: `lanes = { 1: { in, outs:[…], path:[{p, line}], branch?, bpaths? }, 2: {…} }`
- 필수 노드(줄마다 IN/OUT)가 없으면 **즉시 에러**를 낸다. (디자이너 실수를 조기에 발견)
- `extras`는 `node.userData`로 들어온다. `role` 등은 여기서 읽는다.

### 3-2. 모듈 단위 경로 만들기

```js
// pts: [{p: Vector3, line: boolean}]  line=true면 "이전 점 → 이 점"은 직선
function buildLanePath(pts) {
  const path = new THREE.CurvePath();
  let i = 0;
  while (i < pts.length - 1) {
    if (pts[i + 1].line) { path.add(new THREE.LineCurve3(pts[i].p, pts[i + 1].p)); i++; }
    else {
      let j = i + 1;
      while (j + 1 < pts.length && !pts[j + 1].line) j++;     // 이어지는 곡선 점을 한 묶음으로
      path.add(new THREE.CatmullRomCurve3(pts.slice(i, j + 1).map(q => q.p), false, 'centripetal'));
      i = j;
    }
  }
  return path;
}
```

- 점 배열은 `IN → PATH들 → OUT` 순서. PATH가 없으면 `IN→OUT` 직선 하나.
- ⚠️ **three r128의 `CurvePath.getPoint(t, target)`은 `target`을 채우지 않고 새 벡터를 반환**한다. 항상 **반환값**을 사용한다. (최신 버전에서도 동일하게 동작)
- `CurvePath.getPoint(t)`의 `t`는 이미 전체 길이 비례이므로 길이 보정이 필요 없다. 방향은 `u±δ` 두 점의 차로 직접 계산한다.

### 3-3. 자동 연결

`OUT`이 가까운 `IN`과 같은 위치/방향으로 만나면 연결로 판정한다.

```js
function isConnected(outM, inM, posTol = 0.02, dirTol = 0.99) {
  const p1 = new THREE.Vector3().setFromMatrixPosition(outM);
  const p2 = new THREE.Vector3().setFromMatrixPosition(inM);
  const f1 = new THREE.Vector3(0, 0, 1).transformDirection(outM);   // 진행 방향 축은 합의한 규칙에 맞게
  const f2 = new THREE.Vector3(0, 0, 1).transformDirection(inM);
  return p1.distanceTo(p2) < posTol && f1.dot(f2) > dirTol;
}
```

- 연결은 **같은 줄 번호끼리만** (`CONN_1_OUT` ↔ `CONN_1_IN`).
- 위치 허용 오차 2cm 안팎, 방향은 거의 평행(`dot > 0.99`).
- 허용 오차를 넘게 벌어져 있으면 **연결하지 않고 그 줄이 거기서 끝**나는 것으로 처리한다. 큰 틈을 메우면 배치 실수가 숨겨진다. 1~2cm 이내 오차만 직선으로 메운다.
- 스냅 직후 같은 번호 줄의 `OUT`과 `IN` 거리를 모두 검사해서 어긋나면 **경고**를 낸다. (줄 간격이 모듈마다 다른 경우를 발견)
- 줄 수가 다른 모듈끼리는 연결하지 않는다.

### 3-4. 줄(구간) 조립

1. 모든 `(OUT → IN)` 연결을 링크로 저장한다.
2. 들어오는 링크가 없는 모듈에서 시작해 링크를 따라가며 조각을 모은다.
3. 조각들의 경로를 `CurvePath`로 이어 붙인다. 연결점(OUT≈IN)은 하나만 쓴다 (거리 < ε면 건너뜀).
4. 박스는 월드 좌표가 아니라 **줄 경로 위의 거리 `s`** 하나로 관리하고, 위치와 방향은 매 프레임 `s`로 계산한다.

- **출구 1개 → 입구 1개**로만 이어지는 곳은 하나의 구간으로 합친다.
- **분기**(출구가 둘 이상) 또는 **합류**(입구에 연결이 둘 이상)에서만 구간을 끊는다.
- 모듈마다 속도가 다르면 조각별 속도를 들고 있다가 `s`가 속한 조각의 값을 쓴다.

### 3-4-1. 중간 모듈 / 스냅

- `next.root.matrix = prevOut(부모 기준) × inverse(next.CONN_IN 로컬)` 한 번으로 위치와 회전이 모두 맞는다.
- 줄이 여러 개면 **1번 줄 기준**으로 스냅하고 나머지 줄은 따라온다.
- 분기 모듈은 출구가 여러 개이므로 `snapModule(prev, next, outIndex)`로 **어느 출구에 붙일지** 받는다.
- 모든 모듈과 박스는 **같은 부모(Group)** 아래에 둔다. 경로를 부모 기준 로컬 좌표로 계산하기 때문이다.

### 3-5. 박스 이동

- 앞 박스와 최소 간격(`gap`)을 유지한다. 앞에서부터 처리하며 `limit`을 갱신한다.
- **구간 갱신은 하류부터** 한다. 그래야 맨 앞 박스가 다음 구간의 꼬리 박스와 간격을 정확히 유지한다.
- 구간 경계를 넘을 때 `s -= seg.length`로 좌표를 이어 준다.
- 박스 지오메트리의 **원점은 바닥 중심**으로 맞춘다. (경로가 벨트 윗면 높이이므로)
- 스폰은 입구에 자리가 있을 때만 한다.

### 3-6. 분기와 불량 판정

- 분기 모듈은 경로를 세 조각으로 읽는다: `up(IN→BRANCH)`, `out0(BRANCH→OUT_0)`, `out1(BRANCH→OUT_1, BPATH 경유)`.
- 입구 구간의 `next = [합격 구간, 불량 구간]`이고, 구간 끝에서 박스의 `route`로 다음 구간을 고른다.
- **판정은 분기점에 닿기 전에 끝낸다.** 갈래를 알아야 앞 구간 간격 계산이 가능하다. 센서는 분기점보다 충분히 상류(데모에서 1.1 m 앞)에 둔다.
- 불량 여부의 출처:
  - 시뮬레이션: 스폰 시 확률로 결정
  - 디지털 트윈: PLC / MES / 비전 검사 결과를 WebSocket 이벤트로 받아 **박스 ID로 매칭**
- 판정과 출구 결정을 `inspect(it)` 한 곳에 모아 두면, 실제 데이터 연동 시 이 함수만 바꾸면 된다.
- 출구의 의미(`pass` / `reject`)는 `extras.role`에서 읽고, `routes: { OK: 'pass', DEFECT: 'reject' }`로 판정 결과 → 출구를 매핑한다. 이어 붙은 모듈은 `role`을 상속한다.

### 3-7. 푸셔(연출)

- 푸셔는 **타이머가 아니라 불량 박스의 실제 위치**로 구동한다. 속도를 바꿔도 박스와 맞물린다.
- 곡선에서 박스가 회전하면 좌우 폭이 커지므로 접촉면 계산에 **회전한 폭**을 반영한다.
- 푸셔는 연출이며 박스의 실제 경로 선택에는 영향을 주지 않는다.

### 3-8. 에디터(사용자가 배치하는 경우)

- **선을 클릭해서 합격선/불량선을 지정하지 않는다.** 선의 종류는 분기 모듈의 **어느 출구에 이어 붙였는가**로 정해진다. (선과 분기 모듈 설정이 어긋나는 문제 방지)
- 분기 모듈의 출구에 초록(합격) / 빨강(불량) 표시를 띄우고, 사용자가 그 표시에 다음 모듈을 스냅한다.
- 구간(segment)은 **자동 생성**한다. 입구에서 시작해 연결을 따라가다 분기를 만나면 구간을 끊고 출구마다 새 구간을 시작한다.
- 줄 수가 같은 모듈만 붙을 수 있게 막는다.

### 3-9. 제한과 확장 포인트

- 지금 구조는 **분기**까지 지원한다. **합류**는 우선순위/대기 규칙이 추가로 필요하다.
- 모듈 간 겹침(자기 교차)은 검사하지 않는다. 에디터에서는 배치 시 바운딩 박스 검사를 넣는다.
- 박스가 수천 개가 되면 박스마다 재질을 만들지 말고 `InstancedMesh`를 고려한다.
- 벨트 텍스처 스크롤은 공유 텍스처를 **한 번만** 갱신한다. (모듈마다 갱신하면 속도가 배로 보임)

### 3-10. 개발자 체크리스트

- [ ] 필수 Empty 누락 시 에러가 난다
- [ ] `OUT`↔`IN`이 허용 오차 안에서만 연결되고, 벌어지면 줄이 끊긴다
- [ ] 스냅 후 접합부에서 경로가 끊기지 않는다 (경로 표시로 확인)
- [ ] `getPoint`의 반환값을 사용한다
- [ ] 박스 원점이 바닥 중심이고 모듈과 같은 부모 아래에 있다
- [ ] 구간 갱신 순서가 하류 → 상류이다
- [ ] 판정이 분기점보다 충분히 앞에서 끝난다
- [ ] 불량 박스가 100% 불량선으로 가는지 확인했다 (오배송 0건)
- [ ] 속도를 바꿔도 푸셔가 박스와 어긋나지 않는다
- [ ] 같은 줄 번호끼리만 연결되고, 줄 수가 다른 모듈은 막힌다
