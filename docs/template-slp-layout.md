# 템플릿 레이아웃 (SLP) 규칙

템플릿은 `src/constants/templates/*.json` 에 템플릿 하나당 파일 하나로 관리합니다. 파일은 `node scripts/generate-templates.mjs` 가 실측 상수(벨트·스캔 터널·AMR·팔레트·랙 footprint)로 생성하고, `src/constants/sceneTemplates.ts` 가 순서대로 import 한 뒤 `parseTemplates`(`src/domain/layout/templateValidation.ts`)로 검증합니다. 종류, 유한한 pose, floor 정수 크기, link 타입/인덱스(LINK_RULES), id 중복을 확인하고 잘못되면 예외를 던집니다. 직접 수정해도 되지만 생성기를 고치고 다시 생성하는 것을 권장합니다.

## SLP (Muther Systematic Layout Planning) 적용

1. **흐름 / 관계 차트**: 컨베이어 → 스캐너 → 로봇(마지막 로봇이 스토퍼 끝) → 팔레트 → AMR/지게차 → 도크/랙. 관계가 A(절대 인접)인 것은 같은 "존"에 묶고, link(pickup/deliver)로 고정합니다. 각 라인의 AMR은 자기 라인 팔레트만, 팔레트는 자기 존의 도크/랙으로만 갑니다.
2. **공간 소요**: 실측 footprint 기준. AMR 적재 반경 1.244 m + 안전여유 0.1 m → 차선 폭 2.69 m.
3. **흐름 패턴**: 직선(I) 흐름. 라인은 +z 방향, 출고 도크는 라인 하류 끝(스토퍼 너머 3 m), 랙은 통로 바깥쪽 측면(L자)에 둡니다. 라인 두 개는 등을 맞대고(벨트 간격 = 터널 폭 + 0.4 m) 통로는 각자 바깥쪽에 둡니다.
4. **대안 평가**: 600 s 헤드리스 시뮬레이션(`node scripts/flow-check.mjs --at=300,600`)으로 픽 수·출고 수 증가, 영구 정지/교착 여부를 보고 채택합니다.

## 통로 규칙

- 팔레트 열 바깥 모서리 = 벨트 중심에서 3.48 m.
- 1차선(픽업·하역) 중심 4.87 m, 2차선(통과·복귀) 중심 7.56 m, 통로 금지구역 끝 9.05 m → **양방향 통로 유효 폭 5.58 m** (≥ 2×2×1.243 + 여유).
- AMR 대기 위치는 2차선 상류(팔레트 앞쪽). 정상 도크는 1차선, 불량 도크는 2차선 하류 끝.
- AMR 경로는 컨베이어를 가로지르지 않습니다(각 존이 자기 통로만 사용).
- 랙: 통로 금지구역 바깥에 열 간격 4.9 m, 행 간격 7.3 m(행 사이 5.4 m = AMR 인계 + 지게차). 적재면은 -z(라인 상류 쪽)이며 인계 지점은 랙 앞에 있습니다.
- 랙 존에는 지게차 1대, 바깥 벽에 문(지게차 출고용), 랙이 바쁠 때를 위한 보조 도크(1차선, 더 하류)를 둡니다. 보관 구역은 다른 라인 통로를 가로지르지 않도록 한쪽 외곽에만 둡니다.
- 바닥은 장비를 모두 덮도록 정수 셀로 잡습니다.

## 벽 높이

`FACTORY_ROOM.defaultWallHeight` = max(10, ceil((랙 높이 7.55 m + 트러스 깊이 1.1 m + 데크 0.06 m + 여유 0.5 m) / 0.5) × 0.5) = **10 m**. 모든 템플릿과 바닥 그리기 시작 높이에 사용합니다(최대 15 m).

## 팔레트 순환

- **AMR 데크 높이**: `AMR_DECK = AMR_MODEL.deck[1]` (≈ 1.0024 m). `scripts/gen-model-points.mjs`가 AMR.glb의 `AMR_point`에서 생성합니다. 예전 고정값 0.27은 팔레트를 0.73 m 가라앉혔습니다.
- **지게차 ↔ AMR 인계**: 팔레트는 데크 높이에 놓이고, 방향은 팔레트의 월드 yaw를 따릅니다. 놓은 뒤 회전도 초기화합니다. `flow-check`의 `handoff:` 줄은 인계 직전·직후의 위치(xz), 높이(y), 방향(yaw) 차이를 보여주며, 0이어야 정상입니다.
- **Rack_m**: 고정 Rack과 별개의 오브젝트입니다. 에디터에서는 RackMobile로, Play에서는 사이클이 `rackViews`로 그리며 정적 오브젝트에서는 빠집니다. 그래서 같이 선택되거나 두 번 그려지지 않습니다.
- **경로 fallback**: 출발점이나 목표가 장애물 범위 안에 있으면(예: 입하 벨트 끝의 셔틀 홈) `CycleVehicle.planViaApproach`가 주변 링(반경 1 / 1.6 / 2.4 m, 8방향)의 비어 있는 지점까지 경로를 잡고, 마지막 짧은 구간만 직선으로 이동합니다.
- **에셋 프리셋**: 셔틀 AMR, AGV, AMR 교체 지게차, 랙 지게차, Rack_m, 도크 4종(service · palletSource · rackDrop · stage), 팔레트 입하·출하 컨베이어. 각 프리셋에 고스트와 썸네일이 있습니다.
- **셔틀 팔레트**: 셔틀 AMR은 배치할 때 팔레트를 데크에 싣고 나옵니다(`mountedOn`, 함께 이동, undo 한 번에 같이 취소). 상세 패널의 **팔레트 포함** 체크박스로 빼거나 다시 실을 수 있습니다. 팔레트를 빈 AMR 위에 놓으면(0.8 m 이내) 고스트가 데크 높이로 스냅되고, 놓으면 연결됩니다. 서비스 지게차의 만재 ↔ 빈 팔레트 교체 흐름은 셔틀에 팔레트가 있다는 전제로 그대로 동작합니다.
- **상세 패널**: 셔틀, 지게차, AGV, Rack_m의 상세 패널에 '팔레트 사이클' 섹션(역할 · 상태 · 상세)이 있습니다.
- **검증**: `npm run test:mount`는 스냅, 따라 이동, undo/redo, 분리, 삭제 시 해제, 셔틀 자동 팔레트, 팔레트 포함 토글을 확인합니다.
